# إضافة مصحف

الهدف أن تكون الإضافة **عمل بيانات** لا إعادة برمجة. لا تُعدَّل
`MushafPageViewer` ولا واجهة السرد ولا نواة التنقّل.

## ١ — تأكّد من الترخيص أولًا

قبل أي تنزيل: اقرأ `LICENSE` و`NOTICE` والناشر وشروطه. المنتج **تجاري**، فأي أصل
مقصور على الاستخدام غير التجاري **لا يُدمَج** — يُوثَّق كمرشَّح فقط.

## ٢ — أضف المصدر إلى سكربت الاستيراد

في `scripts/fetch-mushaf.mjs` ضمن `SOURCES`:

```js
'warsh-kfqc': {
  base: 'https://.../mushafs/warsh/kfqc/svg',
  pageCount: 604,
  firstPageNumber: 1,
  ext: 'svg',
  ayahCounting: 'madani-first',   // عدّ هذه الطبعة، لا عدّنا
},
```

## ٣ — استورد

```bash
npm run mushaf:fetch warsh-kfqc
```

يكتب الصفحات في `sard/public/mushafs/<id>/pages/` و`manifest.json` يسرد **ما وُجد على
القرص فعلًا** لا ما كان مقصودًا. السكربت يستأنف: الملفّات الموجودة تُتخطّى.

## ٣.٥ — افهرس الصفحات

```bash
npm run mushaf:index warsh-kfqc
```

يقرأ طبقة المضلّعات ويكتب `page-index.json`: أي آيات في كل صفحة **بعدّ هذه الطبعة**.
لا يُنسخ فهرس طبعة أخرى — العدّ يختلف، فالنسخ يسمّي صفحات صحيحة وآيات خاطئة. ويرفض
السكربت أن يكتب فهرسًا لا يضمنه: المضلّعات يجب أن تعدّ كل آيات كل سورة مرّة واحدة
وبالترتيب.

## ٤ — اكتب ملفّ المصدر

`sard/public/mushafs/<id>/PROVENANCE.md`: الناشر · الرابط · الرواية · الشروط · تاريخ
الحصول · ما استُبعد ولماذا.

## ٥ — سجّل الطبعة

في `src/lib/mushaf/registry.ts` أضف مدخلًا إلى `MUSHAF_REGISTRY`. انتبه أن
`pageCount` خاصّ بكل طبعة — مصحف الأوقاف الليبي ٦١٢ صفحة لا ٦٠٤ — وأن `ayahCounting`
عدّ الطبعة نفسها، و`assetBaseUrl` جذر أصولها.

و`pageAlignmentGroup` **ادّعاء يُتحقَّق منه**: لا تضع طبعة في مجموعة ما لم تكن مصفوفة
على حدود صفحاتها فعلًا. اختبار `mushaf-package.test.ts` يفحص الادّعاء على الأصول.
وإن لم تكن مصفوفة فاتركها بلا مجموعة: يُنقل الرقم كما هو ويُعلَّم غير مضبوط، وهذا
أصدق من تحويل مخترع.

## ٦ — تحقّق

```bash
npm run mushaf:validate warsh-kfqc
```

يفحص: اكتمال الصفحات · تطابق الـmanifest مع القرص · وجود `viewBox` · غياب
`<script>` · ألّا تتكرّر آية ولا تنقص من تسلسل سورتها · أن السور الـ١١٤ قابلة
للوصول · أن مجموع الآيات يطابق العدّ المعلَن.

الطبعة بالعدّ الكوفي تُقاس زيادةً على بياناتنا النصّية المستقلّة. أمّا غيرها فلا
تُقاس بحفص إطلاقًا — ورش ٦٢١٤ آية وحفص ٦٢٣٦، فقياس أحدهما بالآخر يُسقِط حزمة سليمة
ويُمرّر حزمة من رواية أخرى.

## مسار آخر: طبعة من PDF

بعض الطبعات لا تُنشر صفحاتها متجهةً، وإنما يوجد الكتاب مطبوعًا وله PDF. الشمرلي
منها. حين يصل ملفّ **مرخَّص**:

```bash
npm run mushaf:from-pdf hafs-shamarly ../shamarly.pdf --probe
npm run mushaf:from-pdf hafs-shamarly ../shamarly.pdf --skip 1 --first-printed 2 --scale 2
```

- `--probe` يقرأ ولا يكتب: عدد الصفحات ومقاسها، وهل فيه طبقة نصّ — وهي التي تقرّر
  إن كانت مناطق الآيات تُشتقّ آليًّا أم تُرسم يدويًّا.
- `--skip` يتخطّى الأوراق الأولى التي لا تحمل قرآنًا، و`--first-printed` هو الرقم
  المطبوع على أوّل صفحة محفوظة (الشمرلي يبدأ عند ٢).
- السكربت **يرفض الكتابة** إن لم يطابق عددُ الصفحات ما يعلنه السجلّ للطبعة: صفحة
  واحدة إزاحةً تعني صفحةً خاطئة في كل ما بعدها.
- يُخرِج WebP مسمّى بالرقم المطبوع، ويكتب `manifest.json`.

ثم في السجلّ: `pageFormat` من `'none'` إلى `'webp'` — ولا شيء غيره. ثم
`PROVENANCE.md`: من أين الملفّ، وبأيّ إذن.

### المناطق فوق صور الـPDF

الصور وحدها تُعرَض ولا تُنقَر. للنقر يلزم `hotspotMode: 'external-json'` وملفّات
مناطق بإحداثيّات مُطبَّعة (٠→١) كما في القسم التالي. إن كان في الـPDF طبقة نصّ
تحمل علامات الآي بأرقامها فقد تُشتقّ منها؛ وإلّا فهي عمل يدوي.

## ٧ — إن لم تكن المضلّعات جاهزة

اضبط `hotspotMode: 'external-json'` وجهّز ملفّات المناطق بإحداثيّات **مُطبَّعة (٠→١)**
حتى تعمل على أي مقاس:

```json
{ "page": 105,
  "ayahs": [{ "surah": 4, "ayah": 171,
    "regions": [{ "type": "polygon", "points": [[0.1,0.25],[0.8,0.25],[0.8,0.31],[0.1,0.31]] }] }] }
```

## ما لا يُفعَل

- **لا OCR** لتوليد نصّ قرآني. النصّ من مجموعة بيانات موثّقة مستقلّة؛ الصورة للشكل فقط.
- **لا نسخ أصول** من قارئ تجاري لا يرخّصها.
- **لا توليد رواية من أخرى**. كل مصحف مصدره طبعة موثّقة.
